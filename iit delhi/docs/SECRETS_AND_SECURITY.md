# Sahara Finance — Secrets & Security Management

## 1. Zero-Secrets Policy

Under no circumstances should production credentials, API keys, private keys, database connection strings containing passwords, or cryptographic tokens be committed to version control.

### Secret Management Standards:
1. **Never commit `.env` files**: All `.env` files must be included in `.gitignore`.
2. **Environment Variable Injection**: In cloud runtime environments (Render, Railway, Fly.io, Vercel), secrets are injected strictly through platform environment variable secret managers.
3. **Comcompromised Secret Protocol**:
   - The previously referenced OmniDimension API key (`OhgDtBtk...`) in documentation/test files has been immediately purged and replaced with standard placeholders (`your_api_key_here`).
   - If an API key was publicly exposed, it must be considered compromised and immediately rotated via the [OmniDimension Dashboard](https://omnidim.io).
4. **JWT Secrets**:
   - `JWT_SECRET` must be a high-entropy string (minimum 32 random characters / 256 bits of entropy).
   - In production, server startup will log a critical security warning if the fallback development secret is detected.

## 2. Environment Variables Specification

| Variable | Sensitivity | Purpose | Recommended Configuration |
| :--- | :--- | :--- | :--- |
| `PORT` | Public | HTTP port | `5000` |
| `NODE_ENV` | Public | Environment indicator | `production` / `development` |
| `MONGODB_URI` | **HIGH** | Database connection string | Atlas cluster connection string with encrypted credentials |
| `JWT_SECRET` | **CRITICAL** | Secret for signing JWT sessions | Secure random 64-character alphanumeric string |
| `JWT_EXPIRES_IN` | Low | Session expiration window | `7d` |
| `OTP_MODE` | Low | Free demo OTP or SMS | `demo` |
| `CLIENT_ORIGIN` | Public | CORS allowed domains | Comma-separated client URLs |
| `OMNIDIM_MODE` | Low | Real API or Mock fallback | `real` / `mock` |
| `OMNIDIM_API_KEY` | **CRITICAL** | OmniDimension platform API key | Generated from provider dashboard; server-side only |
| `OMNIDIM_AGENT_ID` | Low | Saathi Agent ID | Configured agent identifier |
| `OMNIDIM_BASE_URL` | Low | Provider API base URL | `https://backend.omnidim.io/api/v1` |

## 3. Server-Side Protection Architecture

* **Never Leak Secrets to Frontend**:
  - `OMNIDIM_API_KEY` is strictly consumed within backend services ([`client.ts`](file:///./backend/src/services/omnidim/client.ts)).
  - Frontend WebVoice connects using short-lived, ephemeral WebSocket session tokens generated by the backend API (`POST /api/omnidim/session/voice`), never the raw master key.
* **Biometric & KYC Privacy**:
  - Aadhaar scan data is processed ephemerally in memory. Raw document images are never stored in the database or filesystem.
* **Auditability**:
  - All sensitive actions, authorization checks, and failed attempts are recorded in structured security audit logs without persisting raw sensitive inputs.
